# Minimal AI OS — Skill Template

## Purpose

Every skill is a markdown file in `skills/`. It is a Standard Operating Procedure — not code, not a prompt, not an agent. It defines how one atomic type of work is performed.

Skills are procedural knowledge modules. No heavy tooling required.

---

## Required YAML Frontmatter

Every skill file must begin with:

```yaml
---
name: {kebab-case-skill-name}
description: "One-sentence description of what this skill does and when to load it."
version: 1.0.0
author: {your_name_or_agency}
dependencies:
  - editorial-voice.md
  - editorial-gate.md
---
```

**Dependency rules:**
- Always load `editorial-voice.md` before any writing or editing task.
- Always load `editorial-gate.md` as the final step for any content production task.
- Never load more than 4 production skills + dependencies in one task.
- Quick hits (single-skill tasks, output under 200 words) may skip the gate.

## Required Sections

### 1. Purpose

One paragraph. What this skill does and what it does NOT do. Be explicit about scope boundaries.

### 2. What You Receive

Bulleted list of inputs this skill expects:
1. **{Input name}** — from {source}
2. **{Input name}** — from {source}

### 3. Output

Bulleted list of what this skill produces:
- {Deliverable 1}
- {Deliverable 2}
- `## QA` section (appended after editorial-gate.md runs)

### 4. {Skill Body}

The core procedure. Use headers, tables, and code blocks as needed. This is the reasoning framework the AI follows when this skill is loaded.

**Include:**
- Step-by-step instructions
- Decision frameworks (when to choose X vs. Y)
- Examples (marked as "Example:")
- Format templates (marked as "Template:")

### 5. Success Criteria (The Gate)

Define the pass/fail criteria for this specific skill. Use the 5-gate framework or define your own.

**Default 5-Gate Framework:**

| Gate | Question | Pass Condition |
|------|----------|----------------|
| **1. Voice Compliance** | Does this sound like this brand? | Every sentence matches voice attributes; no banned terms |
| **2. Brief Fidelity** | Does it deliver what was asked for? | All elements of the request addressed; format followed |
| **3. Structural Quality** | Is it well-constructed for its format? | Follows format conventions; has beginning, middle, end |
| **4. Factual Integrity** | Are claims sourced or sourceable? | No invented details; quotes from source material; numbers verified |
| **5. Publish Readiness** | Is it clean, complete, and ready to ship? | No placeholders; no [TBD]; consistent formatting; meta data complete |

**Scoring:**
- 5/5 on all gates → **APPROVED** — ship it
- Any gate 3–4 → **REVISE** — return specific line-level notes
- Any gate 1–2 → **KILL** — start over with explanation

### 6. Decision Frameworks

At least one. How does the AI choose between options within this skill?

Example:
```
### Format Selection
1. Is the reader trying to do something? → How-to / tutorial
2. Is the reader comparing options? → Listicle / comparison
3. Is the reader staying current? → News / trend analysis
```

### 7. Source Contract

Required final section. The "do not invent" clause for this skill.

Example:
```
- Do NOT invent concrete details: no specific menu items, no walking distances, no floor counts — unless they appear in the source material.
- Quotes must come from the source material. Never invent a quote.
- If source insufficiency is flagged, write observationally — authority comes from how you see, not what you claim.
```
