# Minimal AI OS — Runtime Specification

## Purpose

The runtime is a dumb courier. It is the only code in the system. Its job is to unlock the door, hand the AI its stack of memos, and let it work.

All intelligence lives in the markdown files. The runtime just reads them and calls the model.

---

## What the Runtime Does

### Night Shift Mode (Default)

Triggered by cron at 02:00 UTC:

```
1. LOAD WORKSPACE
   Read all files in workspace/data/ to build context snapshot.
   Read data_map.md to verify file inventory.

2. READ LOGBOOK
   Read workspace/data/alex-log.md (or logbook.md) to see what was done last run.
   Note any carry-over tasks or blocked items.

3. READ STANDING ORDERS
   Parse standing_orders.md for today's day of week.
   Identify recurring tasks due tonight.
   Identify active projects with approaching deadlines.
   Build the work queue.

4. CONTEXT READINESS CHECK (Pre-Flight)
   For each task in the queue:
     a. Check the skill's dependencies against available files in workspace/data/
     b. Return one of three verdicts:
        - READY: All required context present. Proceed.
        - PARTIAL: Can proceed, but will infer some elements. Flag inferences in output.
        - BLOCKED: Cannot proceed. Halt task, log missing context, move to next task.

5. EXECUTE TASKS
   For each READY or PARTIAL task:
     a. Load the skill file(s) from skills/
     b. Load editorial-voice.md (always)
     c. Assemble prompt: teammate.md + skill + context + task brief
     d. Call the model (Claude, Kimi, GPT-4, local — model-agnostic)
     e. Receive output

6. QUALITY GATE (Post-Execution)
   For each deliverable over 200 words:
     a. Load editorial-gate.md
     b. Run the 5-gate scoring (Voice, Fidelity, Structure, Facts, Publish)
     c. Verdict:
        - APPROVED → proceed to save
        - REVISE → one revision attempt with specific feedback
        - KILL → log failure, do not save, flag in morning report

7. SAVE OUTPUTS
   Write approved deliverables to workspace/work/ with date-stamped filenames.
   Write morning report to workspace/reports/YYYY-MM-DD-morning-report.md.

8. UPDATE LOGBOOK
   Append to workspace/data/alex-log.md:
   - Timestamp
   - Tasks attempted / completed / blocked
   - Deliverables produced with file paths
   - Missing context flagged

9. SHUT DOWN
   Exit. No persistent process. The filesystem is the memory.
```

### Day Shift Mode (Optional)

Replace the single 02:00 run with shorter sprint cycles:

```
Sprint 1 (09:15): Parse standing orders → build queue → pre-flight check
Sprint 2 (11:30): Execute batch 1 → quality gate → save → status update
Sprint 3 (13:00): Human may have added files to workspace/data/ during lunch
Sprint 4 (15:30): Execute batch 2 → quality gate → save → status update
Sprint 5 (17:00): Final handoff report → update logbook → shut down
```

Status updates write to `workspace/reports/status_board.md` instead of a single morning report.

## The Prompt Assembly

The runtime constructs one prompt per task. The prompt is assembled in this order:

```
[SYSTEM: You are the teammate defined in teammate.md]

[CONTEXT: Here is what is in the workspace/data/ folder today]

[TASK: Here is the standing order for tonight]

[SKILL: Here is the skill file to follow]

[VOICE: Here is the editorial voice reference]

[LOG: Here is what you did last time]

[INSTRUCTION: Execute the skill. Follow every step. Run the quality gate before saving.]
```

**No system prompt bloat.** The teammate.md is loaded fresh every run. There is no persistent chat history, no vector memory, no framework state.

## Model Agnosticism

The runtime calls the model via a single function:

```python
def call_model(prompt: str, model_config: dict) -> str:
    # Swap this for any provider:
    # - Anthropic Claude
    # - Moonshot Kimi
    # - OpenAI GPT-4
    # - Local LLM via Ollama
    # - Any OpenAI-compatible endpoint
    pass
```

To swap models, change one line in `runtime.py` or the `.env` file. The markdown files do not change.

## Error Handling

| Failure | Runtime Action |
|---------|---------------|
| Model API down | Log error, retry once in 10 minutes, then halt and notify |
| Skill file missing | Log error, skip task, flag in morning report |
| Context file missing | Pre-flight returns BLOCKED, skip task, flag what is missing |
| Quality gate KILL | Do not save. Log failure. Flag in morning report. |
| Human edited file during run | Human wins. AI logs conflict and does not overwrite. |

## Logging

Every run appends to `workspace/data/alex-log.md`:

```markdown
## Run — YYYY-MM-DD HH:MM

**Mode:** {Night Shift / Day Shift}
**Tasks queued:** [N]
**Tasks completed:** [N]
**Tasks blocked:** [N]

### Deliverables
- [filename] → `workspace/work/{subfolder}/{filename}`

### Blocked / Needs Context
- [Task name]: [What is missing, where it should come from]

### Decisions Logged
- [Question for human] → `decision_log.md`
```
