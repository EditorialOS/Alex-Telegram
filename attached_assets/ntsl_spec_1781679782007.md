# Minimal AI OS — NTSL Specification

## Purpose

NTSL (Natural Task Scheduling Language) is how you program the AI's time without writing code. It is a plain-English domain-specific language that both the human manager and the LLM parse natively.

By using the day of the week as the primary execution toggle, you solve capacity planning: the AI focuses its context window on the right depth of work each day.

---

## Grammar

```
SECTION
  KEYWORD: instruction
  ATTRIBUTE: value
```

**Core sections:** `RECURRING TASKS`, `ACTIVE PROJECTS`, `NOTES`

---

## Template

```markdown
# STANDING ORDERS — {client_name}

## CLIENT INFO
- Client name: {First Name Last Name / Organization}
- Industry: {e.g., hospitality, SaaS, DMO, media, retail}
- Primary contact: {name}
- Contact email: {email}

---

## RECURRING TASKS

### Weekly
- Task: {description}
  Day: {Monday/Tuesday/Wednesday/Thursday/Friday}
  Skill: {skill_file_name}
  Notes: {specifics, constraints, context}

- Task: {description}
  Day: {day}
  Skill: {skill_file_name}
  Notes: {specifics}

### Biweekly
- Task: {description}
  Day: {First Monday / 15th / etc.}
  Skill: {skill_file_name}
  Notes: {specifics}

### Monthly
- Task: {description}
  Day: {First Wednesday / Last Friday / etc.}
  Skill: {skill_file_name}
  Notes: {specifics}

---

## ACTIVE PROJECTS

Project: {name}
Priority: {High / Medium / Low}
Skill: {skill_file_name}
Deadline: {YYYY-MM-DD}
Notes: {strategic context, constraints}

---

## NOTES
- {Any persistent context the AI should know}
- {Channel focus, seasonal hooks, competitive moves}
```

## The Weekly "Flavor" System

Each day has a specific role. This prevents task overlap and ensures depth.

| Day | Role | Focus | Typical Skills |
|-----|------|-------|----------------|
| **Monday** | The Strategist | competitive_analysis, performance_review, quarterly planning | Looks backward at weekend data; sets the tone for the week |
| **Tuesday** | The Producer | build_email_sequence, draft_newsletter, high-volume drafting | Heavy content creation night |
| **Wednesday** | The Auditor | gap_analysis, content_audit, brand consistency check | Reviews what was drafted; finds what's missing |
| **Thursday** | The Promoter | social_distribution_pack, LinkedIn/Twitter assets | Turns the week's work into platform-native content |
| **Friday** | The Planner | create_quarterly_plan, calendar updates, strategic foresight | Looks forward; plans next week/month |

**Skill tiering by frequency:**
- **Daily skills:** Light tasks like check_notifications or summarize_inbox (run every day if needed)
- **Weekly skills:** Heavy tasks like market_repositioning that require reading the entire `/data` folder

## The Day-Shift Alternative (Optional)

Replace the single nightly cron with shorter sprint cycles during business hours:

| Time | Action |
|------|--------|
| 9:00 AM | Standup Report: "Today I will execute X, Y, Z" |
| 9:15 AM | Deep work sprint begins |
| 11:30 AM | Status ping: "Task X complete. Starting Task Y." |
| 12:00 PM | Lunch break. Human reviews morning output. |
| 1:00 PM | Afternoon sprint |
| 3:30 PM | Status ping: "Task Y complete. Task Z 50% done." |
| 5:00 PM | Handoff Report: "Done: X, Y. Blocked: Z needs your input." |

To enable Day Shift, add this block to `standing_orders.md`:

```markdown
## OPERATING RHYTHM
Mode: Day-Shift
Sprint cycles: 9:15-11:30, 13:00-15:30
Status board: workspace/reports/status_board.md
```

## Preventing Redundancy (The Logbook Contract)

Because the AI works multiple days, `logbook.md` is its long-term memory:

- **Tuesday night:** The AI drafts the newsletter and logs: *"Drafted Newsletter V1. Needs client approval on the lead magnet."*
- **Wednesday night:** The AI reads the log before starting. It sees the newsletter is done and *doesn't* touch it again. It moves to the next task.

**Rule:** The AI always reads `logbook.md` before parsing `standing_orders.md`.

---

## Changing Strategy

If the client says *"I want to do more video content,"* you do not rewrite code. You edit `standing_orders.md`:

```markdown
Tuesday:
  - Task: Generate video scripts
    Skill: video-scriptwriter
```

The runtime reads the new instruction on its next run. No deployment needed.
