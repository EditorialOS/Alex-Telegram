# Minimal AI OS — Folder Specification

## Purpose

The filesystem is the brain. There is no database, no vector store, no black-box memory. Every piece of context, every skill, every deliverable, and every log lives in a standard folder structure that syncs between Google Drive and your Hostinger VPS.

If you can drag and drop a file, you can manage an AI worker.

---

## The Root: `ai_os/`

All client workspaces live under one root. For a single-client setup, this is your working directory. For multi-client agencies, duplicate this folder per client.

```
ai_os/
│
├── teammate.md              ← Identity layer (the "Who")
├── standing_orders.md       ← NTSL program (the "When")
├── logbook.md               ← Short-term memory (continuity)
├── decision_log.md          ← Human-in-the-loop parking lot
├── data_map.md              ← Index of what lives in /data
│
├── skills/                  ← Capability layer (the "How")
│   ├── skill_template.md    ← The mold every skill must follow
│   ├── editorial-voice.md   ← Voice & standards reference
│   ├── editorial-gate.md  ← Quality gate reference
│   └── {skill-name}.md     ← One file per atomic skill
│
├── workspace/
│   ├── data/                ← Client context & assets (read-only for AI)
│   │   ├── brand-voice.md
│   │   ├── audience-personas.md
│   │   ├── content-pillars.md
│   │   ├── competitive-landscape.md
│   │   ├── style-guide.md
│   │   ├── standing_orders.md   ← Master NTSL (mirrored root)
│   │   └── alex-log.md          ← Run history
│   │
│   ├── work/                ← Deliverables (write-only for AI)
│   │   ├── drafts/
│   │   ├── social/
│   │   ├── campaigns/
│   │   ├── strategy/
│   │   └── reports/
│   │
│   └── reports/             ← Morning reports & status boards
│       ├── YYYY-MM-DD-morning-report.md
│       └── status_board.md
│
└── runtime.py               ← The engine (the courier)
```

---

## Folder Rules

| Folder | AI Permission | Human Permission | Purpose |
|--------|---------------|------------------|---------|
| `skills/` | Read | Read/Write/Delete | SOPs and reasoning frameworks. The AI loads these at runtime. |
| `workspace/data/` | Read | Read/Write/Delete | Source of truth. The AI reads these before every task. |
| `workspace/work/` | Read/Write | Read/Write/Delete | Deliverables. The AI writes here; the human reviews here. |
| `workspace/reports/` | Read/Write | Read/Write/Delete | Morning briefs, status boards, decision logs. |

**Never overwrite.** Every deliverable is date-stamped: `YYYY-MM-DD-slug.md`.

## File Glossary

| File | Layer | What It Does |
|------|-------|--------------|
| `teammate.md` | Identity | Role, mental model, tone, guardrails |
| `standing_orders.md` | Logic | Weekly rhythm, recurring tasks, active projects |
| `logbook.md` | Memory | What the AI did last night; read before every run |
| `decision_log.md` | Alignment | Questions for the human; AI stops rather than guesses |
| `data_map.md` | Context | Index of data files so the AI doesn't hallucinate missing files |
| `skills/skill_template.md` | Execution | The reusable mold for every skill |
| `runtime.py` | Engine | Loads workspace, assembles prompt, calls model, saves output |

---

## Sync Strategy

- **Primary source:** Google Drive folder (e.g., `Editorial OS / Clients / {client_name}`)
- **Compute location:** Hostinger VPS (or local machine for testing)
- **Sync direction:** Bidirectional via rclone or Drive sync client
- **Conflict rule:** Human edits win. If the AI and human edit the same file between runs, the human version is preserved and the AI logs a conflict note.

---

## Multi-Client Scaling

To onboard a second client, duplicate the `ai_os/` folder and rename:

```
ai_os/
ai_os_client_2/
ai_os_client_3/
```

Each gets its own `teammate.md`, `standing_orders.md`, and `workspace/data/`.
The `runtime.py` engine is shared; only the folder path changes.
